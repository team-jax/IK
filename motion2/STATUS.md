# STATUS (동작 2)

최종 갱신: 2026-10-13

> 동작 2(`motion2/`)의 기록이다. 경로는 `motion2/` 기준이다. 현재 성적과 한계는 `README.md`, 동작 1은 `../motion1/STATUS.md`, 저장소 공통(테스트 도구, 가상환경, 뷰어 환경 문제)은 `../STATUS.md`에 있다.

## 목표

웹캠 손목·손가락 추적으로 최종 URDF(`../URDF_1006/JAXV2_Assembly_description`) 기반 7DOF 팔과 3손가락 손을 MuJoCo에서 제어하고 큐브를 파지한다.

## 완료된 일

- `arm/make_arm_urdf.py`가 최종 URDF에서 `arm.urdf`(ikpy 체인), `arm.xml`(MuJoCo), `meshes/`를 생성
- ikpy FK ↔ MuJoCo `end_effector` site 일치(1e-9), IK 오차 0.00 mm
- 수신기(`src/mujoco_receiver.py`)를 새 관절 구성(7번째 관절이 손 회전, 전완 회전 없음)·손가락 기하에 맞춰 수정
- 화면 없는 시뮬레이션: 큐브가 ±8 mm 어긋나도 접근→하강→닫기→들어올리기 9/9 성공(`scripts/check_grasp.py`), 대시보드 HTTP 응답 확인
- UDP 파이프라인 전체(`scripts/check_teleop.py`): 가짜 송신 스레드 → 수신기 `main()` → IK → 서보 → 접촉 물리로 손을 85 mm 올려 큐브를 들어올림(큐브 중심 z 0.265 → 0.347~0.349). 6필드, 12필드(팔 전체 IK), 팔꿈치 스윙 급점프 3개 시나리오 통과. 깨진 패킷·NaN 위치 패킷이 섞여도 견딤
- 실제 웹캠(2026-10-13): 열림(1920×1080, 30 fps), 송신기가 두 모델을 로드해 14초 동안 오류 없이 돌고 실제 프레임에서 초당 27.8프레임 처리(읽기 11 ms + 포즈 13 ms + 손 11 ms). 화면에 사람이 없어 추적 패킷은 확인하지 못함
- 폴더를 동작 1 구조로 정리(2026-10-13): `src/`, `scripts/`, `models/`, 자체 `README.md`·`STATUS.md`

## 현재 상태

- 모델: `nq=20`, `nu=13`, MJCF 메시 16개(`arm/meshes/`에는 OBJ 16개 + 충돌 STL 6개, 박스 충돌이라 STL은 `JAX_FINGER_COLLISION=mesh`로 생성할 때만 로드)
- 손가락 판은 손 x 방향으로 얇고, 손가락 1·2와 손가락 3(`ROTATION_BASE_ANGLE=-π`)이 마주 본다. 판 안쪽 면 사이 간격은 근위 q=0에서 30 mm, 열림 q=-0.25에서 큐브 높이 기준 약 75~83 mm (2026-10-13 측정)
- 손가락 닫힘은 `FINGER_CLOSED=0.15`, `DISTAL_SCALE=0.1`. `DISTAL_SCALE`이 크면 판이 기울어 큐브 모서리만 물고 들어올릴 때 미끄러진다: 0~0.10은 9/9, 0.15는 7/9, 0.20은 0/9, 0.30은 2/9이고, `DISTAL_SCALE=0.1`에서 `FINGER_CLOSED` 0.10~0.20은 모두 9/9 (2026-10-13, `check_grasp.py` 절차로 측정)
- 12필드 패킷의 팔꿈치 스윙은 ±40°로 제한, 90°/s 이하로 램프, 손가락을 쥐는 동안(평균 curl > 0.3) 고정 (`SWIVEL_LIMIT`, `SWIVEL_MAX_RATE`, `SWIVEL_HOLD_CURL`)
- 알려진 한계: 작업 영역 가장자리(x≥0.19 또는 |y|≥0.15)에서는 손을 수직으로 움직일 때 IK 해가 점프하는 구간이 있다. 스윙을 쓰지 않아도 팔 전체 솔버가 최대 0.26 rad, 손목만 쓰는 palm-down 솔버가 최대 1.8 rad(스윙이 -85° 흘러내림)이고, 큐브 위치 (0.12, 0)에서는 0.01 rad 이하로 매끈하다. 가장자리에서 큐브를 집어 올리면 튕길 수 있다. 원인은 도달 한계가 아니라 풀이다: 상자 안 75개 점 모두에서 손가락 아래 자세의 해가 존재하는데(시작점 16개로 확인, `README.md` 참고) 한 번짜리 풀이가 다른 관절 가지로 간다
- 큐브 30 mm는 윗면 z=0.25인 좁은 기둥 위. 판 끝은 파지 중심(`end_effector`)보다 17.5 mm 아래라, `BASE_Z=0.255`(큐브 바닥보다 5 mm 위)에서 판 끝이 큐브 바닥보다 약 12.5 mm 아래로 내려가 평평한 패드면으로 집는다
- 손가락을 아래로 유지하는 자세는 작업 영역 상자(z≤0.34) 안에는 어디에나 있고, 상자 위로는 몸통에 가까운 앞쪽(x≥0.17, y≈0)부터 닿지 않는다(큐브 위치 (0.12, 0)는 z=0.37에서 위치 오차 15 mm, 0.40에서 41 mm → 0.38 이상 중앙은 불가) → `WORKSPACE_Z=(0.255, 0.34)`

## 문제점과 해결

2026-10-13:

- 최상위에 파일 15개(프로그램 3, 실행 래퍼 3, 검사 4, 스크래치 1, 모델 2, 문서 2)가 섞여 있고 자체 README·STATUS가 없어 설명이 루트 문서에 흩어짐 → 동작 1 구조로 정리: `src/`(프로그램 3), `scripts/`(래퍼 3 + 검사 + `_paths.py`), `models/`(모델 2), `README.md`·`STATUS.md`. 옛 test.py는 다른 검사와 이름을 맞춰 `scripts/check_viewer.py`로, 옛 실행방법.txt는 `README.md`로 합쳤다. 실행 명령이 `motion2/scripts/run_*.sh`로 바뀌었다. `arm/`은 동작 1이 import하므로 그대로 둔다. git에 없던 옛 CAD 폴더(`arm/One_Arm_JAX_URDF_description/`, 19 MB, 코드가 읽지 않음)와 `arm/역운.code-workspace`는 삭제했다
- 이 정리에서 찾은 검사의 구멍: `run_tests.sh`의 파일 글롭이 낡아도(파일을 옮겨 아무것도 못 찾아도) "files parse"로 통과할 수 있었고, `check_docs.py`는 목록의 문서가 없으면 조용히 건너뛰었다 → 필수 글롭이 비면 실패하고, `motion1/` 밖의 문서가 없으면 오류로 처리
- 코드 주석과 문서가 "작업 영역 상자는 손가락이 아래를 유지하는 곳"이라 적고 해결책으로 상자 축소를 제안했는데 측정은 달랐음 → 상자 안 75개 점(x 5 × y 5 × z 3) 모두에서 해가 존재하고(시작점 16개로 풀어 확인), 손이 기울거나 해가 뛰는 것은 이전 자세에서 출발하는 한 번짜리 풀이가 다른 관절 가지로 가기 때문 → 주석과 문서를 정정하고 "다음 할 일"을 풀이 개선으로 바꿈. 높이 한계(중앙 0.38 이상 불가)는 측정으로도 맞았다
- 12필드 패킷에서 팔꿈치 스윙이 급변하면 큐브가 튕겨 나감(`scripts/check_teleop.py swing-jump`) → 원인 셋을 각각 측정: ① `swivel_angle()`이 팔이 수직에 가까우면 기준을 바꿔 측정 스윙이 한 프레임에 90° 뜀, ② 스윙 한계 70°는 큐브 위치에서 들어올릴 때 IK 해가 0.2~0.5 rad 점프하는 범위(±40° 안쪽은 0.02 rad 이하), ③ 큐브를 쥔 채 스윙이 움직이면(20°/s에서 15 mm 미끄러짐, 45°/s 이상이면 튕김) 파지가 흔들림 → 스윙 한계 ±40°, 변화 속도 90°/s, 손가락을 쥐는 동안 고정. 하나씩 빼 보면 ①(한계)과 ③(고정)은 빼는 즉시 실패하고, 속도 제한은 빼도 통과하지만 급변 구간에서 손 이탈이 7.9→2.5 mm, 서보 지연이 0.45→0.10 rad으로 줄어든다. `W_ORIENT`를 올려도(0.05→2.0) 해결되지 않았다(원인이 아니었음)
- 들어올리면 큐브가 손가락 사이에서 빠짐(`check_grasp.py` 0/9, 그때의 설정에서) → 접촉 시 `DISTAL_SCALE=0.3`이 판을 기울여 모서리 접촉만 남음 → `FINGER_CLOSED=0.15`, `DISTAL_SCALE=0.1`로 조정해 9/9 (지금 설정에서 `DISTAL_SCALE`만 0.3으로 되돌려도 2/9로 실패)
- 문서의 수치가 측정과 어긋남(열림 간격 "59 mm" → 실제 75~83 mm, "판 끝이 큐브 바닥보다 7 mm 아래" → 실제 12.5 mm) → 문서와 `src/mujoco_receiver.py` 주석을 측정값으로 정정
