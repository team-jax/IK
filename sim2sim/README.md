# sim2sim — 정우 님 체인(JaxIsaacLab deploy_2026-11-05)을 MuJoCo에서 돌리기

team-jax/JaxIsaacLab `artifacts/deploy_2026-11-05`(main e595900)의 로봇 모델과 정책, 조회표를 한 MuJoCo 장면에 합쳤다. 체인은 Isaac과 같은 순서로 돈다.

> 늘어뜨린 팔 → 들어올리기(조회표) → 대기 → 밀어 넣기 4.5 cm → `grasp_lift_23025` 정책 + 닫기 힘 제어 + 들기 IK → ㄴ자 복귀 → 완료 판정

모든 규칙은 deploy의 `README.md` 7–8절과 `MUJOCO_SIM2SIM.md`를 따랐다. 문서가 모호한 곳은 그 문서가 가리키는 Isaac 코드를 읽어 맞췄다. 배치, 서 있는 방향, 관절 부호, 좌표계는 모두 정우 기준이다. 동작 1·2와는 독립이며, 시각 메시만 `motion2/arm/meshes`의 OBJ를 쓴다(아래 호환성 1번).

## 실행

```
venv/bin/python sim2sim/build_scene.py      # deploy/robot_v3 URDF → jax_v3_scene.xml (생성 파일)
venv/bin/python sim2sim/check_spec.py       # 배치·순운동학·조회표·정책을 deploy 문서 수치와 대조 ("spec ok")
venv/bin/python sim2sim/run_eval.py         # MUJOCO_SIM2SIM.md 3절 평가 → sim2sim/results/ (약 2분)
venv/bin/python sim2sim/render.py --spot 2 28 45 --out sim2sim/results/x2_y28.mp4   # 큐브 (x cm, y cm, 각도) 영상
venv/bin/mjpython sim2sim/render.py --spot 0 0 0 --view                            # 뷰어로 재생 (macOS)
venv/bin/python sim2sim/creep_test.py       # 마찰 설정별 미끄러짐 시험 (호환성 5번)
```

`./run_tests.sh`가 생성기 출력, `check_spec.py`, 기준 큐브 체인을 검사한다. `--full`은 27곳 평가도 돌린다.

| 파일 | 내용 |
|---|---|
| `deploy/` | 정우 님 deploy 폴더에서 가져온 원본: `robot_v3` URDF와 충돌 STL, 정책 `grasp_lift_23025.pt`·`grasp_lift_23025.onnx`·`grasp_lift_23025_meta.json`, `raise_grid_v65_*`, `pregrasp_grid_v65_*`, `hand_theta_v65`, `reach_mask_v65`, 넘겨주기 기록 예, `README.md`, `MUJOCO_SIM2SIM.md`. 고치지 않는다 |
| `build_scene.py` → `jax_v3_scene.xml` | URDF에서 MuJoCo 장면 생성. 책상, 큐브, 바닥, 액추에이터 14개 |
| `chain.py` | 체인 제어기(7.1–7.8), 관측 45개(8.1), 패드 센서(6절), 정책 실행 |

### 정우 님 관절 이름 ↔ 동작 1·2 관절 이름

같은 로봇이고 같은 두 관절의 부호를 뒤집는다(V2 규약). 이름만 다르다.

| 정우 님 (Isaac 번호) | 정우 님 의미 | 동작 1·2 이름 |
|---|---|---|
| `shoulder_pitch_to_shoulder_roll` (0) | 어깨 피치 | `shoulder_roll` |
| `shoulder_roll_to_shoulder_yaw` (1) | 어깨 롤 | `shoulder_yaw` |
| `shoulder_yaw_to_upper_arm` (2) | 어깨 요(위팔 회전) | `upper_arm_roll` |
| `upper_arm_to_under_arm` (3) | 팔꿈치 | `elbow` |
| `under_arm_to_wrist_pitch` (4) | 아래팔 롤 | `wrist_pitch` |
| `wrist_pitch_to_wrist_yaw` (5) | 손목 피치 | `wrist_yaw` |
| `wrist_yaw_to_hand_base` (6) | 손목 요 | `hand_roll` |
| `hand_base_to_rotation_base` (9) | RotationBody | 동작 1·2는 −π에 고정 |

동작 1의 실물 배치(`JAX_SETUP=real`)는 방향과 높이가 정우 님과 같지만 책상이 더 가깝다. 어깨축에서 책상 모서리까지 동작 1은 14 cm(받침대 기둥 면에서 10 cm), 정우 님은 22.5 cm다. 이 폴더는 정우 님 값을 쓴다.

## 호환성 문제와 처리

Isaac(PhysX)과 MuJoCo가 달라서 생긴 문제다. 정우 님 사양을 바꾼 것은 없다. MuJoCo가 PhysX처럼 움직이게 하는 설정만 넣었고, 각 설정은 넣기 전과 후를 쟀다.

| # | 문제 | 처리 | 넣기 전 / 후 |
|---|---|---|---|
| 1 | MuJoCo는 DAE(시각 메시)를 못 읽는다 | robot_v3 DAE 17개가 리포의 `URDF_1108`과 바이트까지 같아서, 그것을 변환해 둔 `motion2/arm/meshes/*.obj`를 시각 메시로 쓴다. 충돌은 정우 님 STL 그대로 | 시각만, 물리 무관 |
| 2 | venv(Python 3.14)에 torch·onnxruntime이 없다 | `.pt`(torch zip)를 numpy로 직접 읽는다(`ptload.py`). 새 라이브러리 없음 | 가중치가 ONNX 파일 바이트와 같음, 정규화 값 = meta |
| 3 | PhysX 관절 속도 상한(`velocity_limit_sim=1.0`, 팔·손가락)이 MuJoCo에 없다. 없으면 정책이 끝마디 굽힘을 크게 바꿀 때 손가락이 4–5 rad/s로 돌아 큐브를 친다 | 물리 스텝마다 로봇 관절 속도를 ±1 rad/s로 자르고, 그 속도로 위치를 다시 적분한다(반암시적 오일러의 `q' = q + dt·v'`라서 적분기 안에서 자르는 것과 같음) | 기준 큐브, MuJoCo 기본 접촉: 손가락 최대 5.5 rad/s → 1.0 rad/s(그래도 큐브가 튐, 4번 문제). 4·5번을 넣은 뒤 상한을 끄면 26/27(진단, 아래) |
| 4 | MuJoCo 접촉이 부드럽다. 기본(`solref` 0.02 s)에서 40 g 큐브에 걸리는 접촉 강성이 약 100 N/m라, kp 40 손가락이 큐브에 6–24 mm 파고든 뒤 큐브를 튕겨 낸다. PhysX(TGS, 위치 반복 8회)는 거의 단단하다 | MuJoCo 스텝을 1/1200 s(PhysX 스텝 하나에 10번)로 나누고 접촉 시간 상수를 0.002 s로 둔다(MuJoCo는 2스텝 이상 필요) | 기준 큐브: 큐브가 88 cm 튐 → 손가락이 0.62 s에 세 개 다 닿음 |
| 5 | MuJoCo 마찰 구속도 부드러워, 정지 마찰 한계 안에서도 쥔 큐브가 조금씩 미끄러진다(creep). PhysX에는 없다 | 타원 마찰 원뿔 + `impratio` 10(MuJoCo 문서가 미끄럼 방지로 권하는 값, 결과를 보기 전에 정함). 마찰 계수는 그대로 | 두 패드로 정지 한계의 절반 하중을 주고 집었을 때 미끄러짐: MuJoCo 기본 2.7 mm/s, 4번만 넣고 `impratio` 1이면 0.23 mm/s, 10이면 0.023 mm/s(5 s 동안 0.1 mm). 기준 큐브의 넘겨줄 때 기울기: `impratio` 1 34°, 10 14° |
| 6 | 마찰 결합: PhysX는 두 재질의 평균, MuJoCo는 큰 값을 쓴다. MuJoCo는 정지·동마찰을 구분하지 않는다 | 로봇 0.4, 큐브 0.4, 책상 0.8로 두면 모든 쌍이 PhysX 평균(큐브–로봇 0.4, 큐브–책상 0.8, 로봇–책상 0.8)과 같다. 정지 마찰 값을 쓴다(동마찰 0.35 / 0.675는 못 넣음) | — |
| 7 | 고정 링크: Isaac은 받침대·어깨 피치·Holder를 합친다(`merge_fixed_joints`) | 관절 없는 몸체로 둔다. 고정이라 동역학이 같다 | — |
| 8 | 자체 충돌: 정우 님 설정은 꺼져 있다(`self_collision=False`) | 로봇 충돌 형상끼리는 비트마스크로 제외, 로봇–큐브·책상·바닥만 충돌 | — |
| 9 | 중력 보상 τ_g: Isaac은 PhysX `get_gravity_compensation_forces` | `mj_rne`(속도 0, 가속도 항 끔). 큐브 제외는 같음 | 밀어 넣기 끝 자세가 README 사전 파지 자세와 0.04° 안 |
| 10 | 좌표: Isaac 시뮬은 로봇을 z −0.0575에 두었다(문서 좌표 = 시뮬 z + 0.0575) | 문서 좌표(바닥 z = 0)에 그대로 둔다. 넘겨주기 기록과 비교할 때만 0.0575를 더한다 | 순운동학 0.07 mm |
| 11 | 놓는 범위 판정: Isaac은 `floor((x − x0)/간격)`인데, 격자선 위의 위치(예: x +2 cm, y ±28 cm)는 float32 반올림에 따라 칸이 바뀐다 | 위치를 품는 칸 중 네 꼭짓점이 모두 유효한 칸이 하나라도 있으면 유효 | README 10절 범위와 같음(x +2: ±28, x 0: −26–+28, x −8: −18–+22, x −14: −10–+8 cm) |

**확인하지 못한 것**
- Isaac URDF 임포터의 충돌 근사는 Isaac Lab 기본값(볼록 껍질)으로 보았다. MuJoCo도 볼록 껍질이다. 정우 님 설정 파일에는 명시돼 있지 않다.
- PhysX 접촉 다양체(patch friction)는 흉내 내지 않았다. 아래의 남은 차이(쥔 큐브가 더 기욺)가 이것 때문인지 확인하지 못했다.
- 속도 상한을 PhysX가 실제로 어떻게 거는지(해결기 안 구속인지, 자르기인지)는 확인하지 않았다.

**README와 코드를 대조해 맞춘 곳** (README가 짧거나 모호했던 곳)
- 엄지 패드 힘: 관측(39·42번)과 완료 판정에는 접촉력 크기를, 닫기 힘 제어에는 −f_x(패드 수직)를 쓴다. 손가락 1·2와 엄지 모두 링크 좌표계의 −f_x다(`JaxV2PadSensorGraspEnv.pad_forces`, `JaxV2FrontGraspEnv.pad_forces`).
- 7.7–7.8 순서: 매 스텝 복귀 시작 판정 → 복귀 목표 → 복귀 시계 + dt → 완료 판정 → (복귀 중이 아니면) 들기 IK(`_lift_return_step`, `_lift_done_update`).
- 복귀 중 행동 7–10 고정: 원시 행동 자리에 복귀 시작 때의 필터 값을 넣고, 필터를 그대로 돌린다.
- 들기 IK 야코비안은 손 링크 원점 기준이고(`mj_jacBody`), 손끝 중점으로 옮긴다.

  | (−8, +18, 35°) | 1/8 |

  그래서 27곳 하나씩의 성패, 그리고 23과 26의 차이는 이 크기의 잡음 안에 있다.

**남은 차이와 실패**
- **쥔 큐브가 Isaac보다 더 기운다.** 넘겨줄 때 기울기 중앙값이 16°로 Isaac의 9.6°보다 크다. `impratio` 100이면 11°라서 마찰 구속의 부드러움이 일부 원인이다. 하지만 평행 미끄러짐 시험(호환성 5번)에서는 10과 100 모두 무시할 수준이라, 회전 방향 미끄러짐이나 접촉점 수(PhysX patch friction) 차이로 보인다. 확인하지 못했다.
- **(−8, +18) cm 35°는 꾸준히 실패한다(1/8).**
  - 손가락 1이 큐브에 끝내 닿지 않아 손가락 2와 엄지 두 점으로만 쥔다.
  - ㄴ자 복귀 0.4 s 뒤 큐브가 돌면서 빠진다.
  - 손에서 본 큐브 각도 ψ는 35° − (−31.9°) = 66.9°로, 정육면체라 −23.1°와 같다.
- **나머지 실패 3곳은 위치를 0.5 mm만 바꿔도 대부분 성공한다.** (−14, +6, −45°)는 엄지가 밀어 넣기 끝에 이미 큐브에 닿아 있다.
